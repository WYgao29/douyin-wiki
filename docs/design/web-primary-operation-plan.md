## 1. 文件目的

本文件用于指导后续编码 Agent，把抖库改造成以 Web 为日常操作主入口的本地知识工作台。

目标不是简单增加几个按钮，而是让普通操作者在 Web 中完成从来源接入、授权、选择、确认、后台处理、人工干预、AI 整理、知识入库，到历史、失败恢复和日常运维的完整闭环。

完成后，CLI 和 MCP 仍然保留，但定位调整为：

- CLI：首次安装、Web 无法启动时的故障恢复、高级维护和开发调试。
- MCP：外部 Agent 自动化、Gateway 分析接续和第三方集成。
- Web：用户所有日常操作的默认入口。

## 2. 执行约束

本方案的所有实现工作必须发生在 `/Users/weisengao/Documents/ChatGPT/douyin-wiki-web-primary`。原始仓库 `/Users/weisengao/Documents/ChatGPT/douyin-wiki` 仅用于只读参考其中尚未提交的文档，不得在原始仓库执行代码修改、格式化、提交、重置或清理。

### 2.1 必须遵守

- 保留 FastAPI、Jinja2、原生 HTML/CSS/JavaScript 技术栈。
- 不引入 React、Vue、Svelte、Tailwind、外部 CDN 或前端构建链。
- 复用现有 service、favorites、creator、database、worker 和 adapter 能力；Web 不通过拼接 CLI 命令执行业务。
- 保持 Web 只绑定 `127.0.0.1`，不得放宽同源、TrustedHost、CSP、媒体路径校验或其他安全边界。
- 所有会下载媒体、调用 AI、写入知识库、执行维护或删除数据的动作，都必须有明确语义和必要确认。
- 不展示或返回 Cookie、密码、Local Storage、API Key 明文。
- 现有 API 和 CLI/MCP 行为尽量保持兼容；新增字段优先采用向后兼容方式。
- 数据库变更必须使用增量迁移，不得破坏现有 Vault、SQLite、聊天、任务和知识资料。
- 自动化测试只使用临时 Vault、模拟页面和固定样例。
- 未经用户单独授权，不得读取、扫描、下载或导入用户的真实抖音收藏、博主作品或其他个人数据。
- 不安装、不重启现有常驻服务，不执行真实全量导入。
- 开始修改前确认当前目录和分支分别为 `/Users/weisengao/Documents/ChatGPT/douyin-wiki-web-primary` 与 `codex/web-primary-operation`，然后检查 `git status`；不得覆盖或清理不属于本任务的修改。

### 2.2 不属于本次目标

- 公网、局域网或多用户 Web 服务。
- 移动端分享扩展、SaaS、跨设备同步。
- 修改抖音收藏、关注或账号资料。
- 定时自动导入个人收藏或博主全部作品。
- 改写 Vault 的核心资料格式。
- 为实现 UI 而绕过现有任务状态机、授权门槛或确认规则。

## 3. 当前能力与主要缺口

当前 Web 已有：

- 资料库浏览、搜索、筛选、文章阅读和收藏。
- 单条抖音链接或分享文案提交。
- 收藏批次的清点、选择、确认、历史恢复和失败重试基础能力。
- 专题、AI 对话、灵感确认、模型设置和废纸篓。
- 单任务状态读取及部分失败重试。

当前 Web 尚不能覆盖：

- 独立、持续可见的抖音授权状态及 Web 授权操作。
- 视频授权和专用抖音浏览器授权的清晰区分。
- 博主主页作品的完整清点、选择、确认、同步和历史操作。
- 全局任务列表、批次/子任务关系、等待本人操作的统一入口。
- 长视频批准、ASR/OCR 人工复核、Gateway 等待状态的 Web 闭环。
- 收藏导入面向操作者的线性流程，以及真正的“更新收藏”语义。
- Worker、Web、模型、外部工具和存储的运行状态。
- maintenance、database rebuild 等日常维护的安全 Web 入口。
- 导入历史、收藏缓存、任务日志和知识资料之间明确的删除边界。

因此不能只重做收藏弹窗，必须同时补齐授权中心、导入中心和任务中心。

## 5. 首页

首页提供运行概览，不承担复杂配置：

- 两条抖音授权通道状态。
- Worker 状态、队列长度和最后心跳。
- AI 分析模式及是否可用。
- 正在执行、等待本人操作、失败和最近完成任务数量。
- 最近导入批次和结果。
- “导入单条”“导入博主”“更新我的收藏”三个主操作。

当存在阻断问题时显示可操作告警，例如：

```text
视频授权已失效，3 个任务已暂停。
[立即授权] [查看这 3 个任务]
```

告警必须链接到具体修复动作，不能只显示错误码或建议用户打开终端。

## 6. 授权中心

### 6.1 两条授权通道

| 通道 | 对应能力 | 会话来源 |
| --- | --- | --- |
| 抖音账号授权 | 收藏清点、博主清点、静态图文采集 | 抖库专用 Playwright Profile |
| 视频下载授权 | 视频访问和 yt-dlp 下载 | 配置中的浏览器 Cookie 来源 |

专用浏览器已经登录，不得因此报告视频下载授权也已就绪。

### 6.2 状态模型

统一展示以下用户状态：

- 未授权
- 授权中
- 已授权
- 可能有效但未完成服务器验证
- 授权已过期
- 需要重新登录
- 检查失败

每张授权卡至少显示：

- 用途说明。
- 非敏感账号信息（能够安全识别时）。
- Cookie/Profile 来源的用户化说明。
- 上次检查时间。
- 受影响的等待任务数量。
- “授权”“重新授权”“检查状态”“查看受影响任务”操作。

### 6.3 Web 授权流程

```text
用户点击授权
→ 后端创建授权会话
→ 启动对应本机浏览器
→ Web 轮询或通过 SSE 接收状态
→ 用户完成登录/扫码/验证码
→ 后端执行非敏感验证
→ 授权成功
→ 自动恢复同一 auth_scope 中允许自动恢复的暂停任务
```

授权会话需要处理：浏览器启动失败、Profile 锁冲突、超时、用户稍后处理、账号变化和外部页面结构变化。

不得将后台线程或子进程对象当作持久状态；数据库只保存非敏感的授权会话 ID、范围、阶段、时间和错误摘要。

## 7. 导入中心

三种来源共享统一入口、状态语言和任务中心，但各自保留适合的选择流程。

### 7.1 单条链接

线性流程：

```text
粘贴链接或分享文案
→ 补充导入选项
→ 提交前检查
→ 确认提交
→ 跳转任务详情
```

表单至少包含：

- 分享文本或链接。
- 一条或多条用户灵感。
- 可选原话及开始/结束时间绑定。
- 媒体保留策略。
- 是否预先批准长视频。
- 是否允许进入可能消耗 Token 的 AI 阶段。
- 当前分析模式及简短费用提示。

提交前检查只报告问题，不应偷偷执行真实下载或 AI 分析。提交后返回并打开任务详情，不只显示瞬时 toast。

### 7.2 博主主页

线性流程：

```text
输入博主主页或该博主任意作品
→ 检查抖音账号授权
→ 清点作品
→ 浏览并选择
→ 确认导入
→ 批次处理
→ 查看结果或同步历史
```

清单页面支持：

- 博主头像、名称、标识、作品数量和上次同步时间。
- 清点完整性说明。
- 搜索、分页、全选、全不选、反选。
- 待导入、已入库、处理中、已排除、不可用筛选。
- 服务端整份清单选择，不能误实现为仅当前页选择。
- 不完整清单的额外确认。
- 已确认批次不可随意修改选择。

博主管理页面支持：

- 查看已有博主。
- 查看作品及历次导入。
- 手动同步。
- 导入以前跳过的作品。

不得在用户未操作时自动订阅或定时同步博主。

### 7.3 我的收藏

现有收藏弹窗改为独立线性流程：

```text
授权我的抖音
→ 更新收藏内容
→ 选择范围和内容类型
→ 浏览并选择作品
→ 确认导入
→ 查看批次执行结果
```

用户界面不再使用“目录读取”“directory only”“清点模式”等实现术语。

“更新我的收藏”分为：

- 增量更新：默认日常操作，合并新发现作品和状态变化。
- 完整更新：从头核对当前可访问范围，用于故障恢复或主动校验。

更新不是简单刷新本地任务状态。只查看历史不得访问抖音；点击更新才发起新的远端读取任务。

收藏列表展示：

- 封面、标题、作者、收藏夹、内容类型和发布时间。
- 新发现、待导入、已入库、处理中、已排除、失败、不可用、需要授权、不支持。
- 搜索、收藏夹筛选、状态筛选和“只看新增”。
- 全选、全不选、反选和跨页选择。
- 作品列表完整性与收藏夹归属完整性分别显示。

确认摘要至少显示：

- 选择的收藏夹。
- 选择的作品数及视频/图文分布。
- 已入库跳过数。
- 复用进行中任务数。
- 预计新建任务数。
- 清单是否完整。
- 是否可能进入 AI 阶段。

文章等不支持类型保留在清单中并标记原因，不静默丢失。

## 8. 统一任务中心

### 8.1 任务列表

任务中心统一显示：

- 单条采集任务。
- 博主清点和导入批次。
- 收藏清点和导入批次。
- 媒体恢复和重分析任务。
- 可观察的专题生成或维护任务。

支持按来源、状态、阶段、时间和“需要本人操作”筛选。

### 8.2 用户阶段

底层状态映射为稳定的用户阶段：

```text
准备
读取来源
下载内容
本地提取
AI 整理
写入知识库
完成
```

底层状态码仍保留在诊断区和 API 中。所有任务返回统一的：

- `state` / `state_label`
- `stage` / `stage_label`
- `progress`
- `message_for_user`
- `next_action`
- `retryable`
- `requires_user_action`
- `updated_at`

### 8.3 等待本人操作

任务中心集中处理：

- 抖音或视频重新授权。
- 长视频继续处理确认。
- ASR/OCR 低置信疑点复核。
- 可重试失败。
- 清单不完整的导入确认。

任务详情展示时间线、当前步骤、错误原因、推荐动作、批次统计、子任务列表、AI 消耗提示和最终资料入口。

批次中的单条等待或失败不应阻断其他可执行子任务。父任务统计必须区分成功、跳过、处理中、等待操作、失败和不可用。

### 8.4 更新机制

优先使用统一 SSE 事件通知任务、授权、服务健康和资料库变化；保留低频轮询作为断线降级。页面关闭和重新打开后必须从持久状态恢复，不依赖浏览器内存。

## 9. AI 与人工复核

### 9.1 三种分析模式必须如实呈现

| 模式 | Web 能否自动闭环 | 显示文案 |
| --- | --- | --- |
| provider | 可以 | 后台模型接口自动整理 |
| local | 可以，但为降级结果 | 本地模式，不调用外部模型 |
| gateway | 当前不能单靠 Web 自动闭环 | 等待外部 Agent 接续 |

不得把 Gateway 模式中的“待 AI 处理”描述为后台正在自动分析。

若产品目标是无需外部 Agent 的 Web 闭环，应引导用户配置 provider 或选择 local；不得静默切换分析模式。

### 9.2 Web 操作

Web 需要支持：

- 在提交前说明是否可能消耗 Token。
- 明确批准长视频或云端分析。
- 展示 ASR/OCR 疑点及对应时间范围或图片编号。
- 修改疑点、逐条接受或接受全部不确定内容。
- 对已入库条目发起重分析。
- 展示分析模式、模型、生产者和可用的 Token 使用统计。
- Gateway 模式下显示接续说明和持久等待状态。

## 10. 历史、缓存和删除边界

必须使用不同名称和确认文案：

| 操作 | 删除内容 | 明确保留内容 |
| --- | --- | --- |
| 删除导入记录 | 可删除的批次展示历史 | 已入库资料、抖音收藏 |
| 清除收藏缓存 | 本地收藏目录和作品清单缓存 | 已入库资料、抖音收藏 |
| 清理任务日志 | 符合保留规则的已结束事件 | 知识资料和未完成任务 |
| 移入废纸篓 | 一组知识资料及关联文件 | 抖音平台内容 |
| 彻底删除 | 废纸篓中的对应资料 | 不保证应用内恢复 |

所有删除操作必须：

1. 先查询并展示影响数量。
2. 明确列出会删除和不会删除的内容。
3. 要求二次确认。
4. 返回实际处理结果和可恢复性。

不得提供语义模糊的“清除全部历史”。

## 11. 系统设置与运维

### 11.1 服务状态

显示：

- Web 版本和运行状态。
- Worker 是否运行、最后心跳、正在处理的任务和队列长度。
- 当前分析模式及模型连接状态。
- Vault、SQLite、Playwright、yt-dlp、ffmpeg、转录和 OCR 状态。
- 最近一次维护和索引重建结果。

### 11.2 安全操作

可提供：

- 重新运行 doctor。
- 请求 Worker 重载或重启；实现前必须确认与 LaunchAgent 的职责边界。
- maintenance 预览和确认执行。
- database rebuild 预览和确认执行。
- 媒体空间及保留策略查看。

维护和重建必须沿用“预览 → 展示错误和影响 → 明确确认 → 执行”的两阶段流程。

首次初始化、Web 服务尚未安装或 Web 自身无法启动时，继续使用 CLI，不要求实现不可能的纯 Web 自举。

## 12. 后端接口规划

具体 URL 可以按现有代码风格微调，但必须形成以下能力，而不是在前端模拟状态。

### 12.1 授权

- 查询所有授权通道的非敏感状态。
- 对指定 scope 发起授权会话。
- 查询或订阅授权会话状态。
- 取消/稍后处理授权会话。
- 授权完成后恢复匹配任务。

### 12.2 任务

- 分页查询全局任务。
- 查询单任务及事件时间线。
- 查询批次子任务和统计。
- 重试任务或批量失败项。
- 批准长视频。
- 提交人工复核结果。
- 返回统一 `next_action`。

### 12.3 博主

- 创建清点。
- 获取清单、完整性和选择统计。
- 跨页设置选择。
- 确认导入。
- 获取博主和作品历史。
- 手动同步及导入已跳过作品。

### 12.4 收藏

- 增量或完整更新收藏。
- 获取目录、清单和更新差异。
- 跨页选择和确认导入。
- 查询批次历史和详情。
- 重试失败项。
- 删除允许删除的历史记录。
- 清除本地收藏缓存。

### 12.5 系统

- Worker 和队列健康状态。
- doctor 结构化结果。
- maintenance 预览和确认执行。
- database rebuild 预览和确认执行。
- 存储和媒体统计。

所有写接口继续执行同源校验、严格 Pydantic 参数校验、稳定错误码和服务端状态门槛。

## 13. 前端实现原则

- 按页面拆分原生 JavaScript 模块，避免继续把所有逻辑堆入 `app.js`。
- 建议至少拆分 `imports-single.js`、`imports-creators.js`、`imports-favorites.js`、`jobs.js`、`auth.js` 和 `system-settings.js`。
- 共享 API、SSE、toast、dialog、时间格式和状态映射工具集中管理。
- 列表超过合理规模时使用服务端分页；批量选择语义由服务端持久化。
- 页面刷新、浏览器前进后退和直接访问 URL 均能恢复正确视图。
- 所有 Dialog 管理焦点，支持 Escape、键盘导航、减少动画和 320px 重排。
- 状态不能只用颜色表达；图标、文字和可访问名称同时存在。
- 加载、空数据、读取失败、部分数据、无权限和离线状态必须分别呈现。

## 15. 测试要求

至少覆盖：

- 未授权、授权中、成功、过期、超时、账号变化和 Profile 锁冲突。
- 视频授权与专用浏览器授权互不误报。
- 单条提交选项完整持久化。
- 博主清单完整/不完整、跨页选择、重复确认和同步。
- 收藏增量/完整更新、未分组作品、多收藏夹去重和跨页选择。
- 已入库跳过、进行中复用、父子任务汇总和崩溃恢复。
- 长视频批准、人工复核、Gateway 等待和 provider/local 完成。
- 授权失效后从 Web 恢复原任务，不重复创建任务。
- 删除历史、清除缓存、资料废纸篓互不误删。
- maintenance 和 rebuild 未确认时绝不执行。
- URL 直达、刷新恢复、浏览器前进后退、SSE 断线降级。
- 键盘、焦点、320px、减少动画、亮暗主题和非颜色状态表达。
- 跨来源请求、恶意路径、非法状态转换和敏感字段泄漏被拒绝。

## 16. 总体验收场景

在临时测试 Vault 和模拟来源中完成以下连续场景：

1. 打开 Web，看到视频授权失效和 Worker 正常。
2. 在 Web 发起视频授权，授权成功后恢复暂停任务。
3. 提交一条抖音分享文案并填写灵感。
4. 对长视频执行明确批准。
5. 处理一条人工复核疑点。
6. 任务完成后直接打开知识资料。
7. 新建博主清点，跨页选择作品并确认导入。
8. 更新个人收藏，只看新增作品并选择导入。
9. 在任务中心查看两个批次及其子任务统计。
10. 重试一个模拟失败项。
11. 删除一条导入历史并清除收藏缓存，确认已入库资料仍存在。
12. 预览 maintenance 和 rebuild，未确认时数据库和文件不发生变化。

## 17. 完成定义

只有满足以下条件才可以宣布完成：

- 除首次初始化、Web 自身故障和高级调试外，日常操作不需要 CLI。
- 单条、博主和收藏三条来源链路均从 Web 完成。
- 授权、长视频批准、人工复核、失败重试均有 Web 操作。
- 全局任务中心准确展示父子任务和等待本人操作。
- AI 三种模式没有错误承诺，Gateway 外部依赖被明确标识。
- 删除和清理操作边界清楚，并由服务端强制确认。
- 自动化测试不访问真实个人数据。
- 现有资料库、专题、对话、模型设置、废纸篓、CLI 和 MCP 回归通过。
- 文档明确说明哪些经过模拟验证，哪些尚未经过真实抖音端到端验证。
